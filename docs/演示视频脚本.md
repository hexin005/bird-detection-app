## 三、功能演示段（镜 3–11）录制要点

1. **按镜号顺序一次录完，不用追求一遍过**——每镜之间留 2 秒静止，后期按镜号切。
2. 检出告警的时机不可控：先试录一次记下"哪一秒弹提醒"，正式录时口播提前半句。
3. 图片提问前把图片放在桌面，选择器弹窗不录进画面（OBS 可裁剪区域）。
4. 3D 沙盘先在后台预热（加载完 WebGL 再正式录），避免录到白屏加载。
5. 每个操作后停 1 秒再说话，方便后期对轨。

## 四、AI 协同过程复现段（镜 12，≥2 分钟硬性）——三选一

### 方案 A（推荐）：录一段真实的新迭代
直播式录屏：在 ZCode 里输入一段真实 Prompt → 让 AI 实现一个**真实存在的小需求** → 展示 AI 的方案 → 验证测试通过。
- **最佳选题**：「驱离联动轻量 Agent」（AI 回答防鸟建议时附"去驱离"按钮，一键带参数跳驱离确认）——既是路线图里的真实需求，又直接呼应"驾驭 AI 智能体"这条 20% 评分项。
- 口播骨架："第一步，我用一句自然语言描述需求（读出 Prompt）；第二步，AI 先核实代码现状再出方案（指一下它读文件）；第三步，方案里哪些点我要求它收敛（说一个你真实的取舍）；第四步，测试全绿、功能验收（点一下真机）。"
- **注意**：录之前把这段 Prompt 的完整对话导出/截图，补进 `docs/prompts/`，与视频互相印证。

### 方案 B：回放历史会话 + 讲解
打开 `docs/prompts/chain-2-ai-assistant.md` 配合 ZCode 历史会话，讲"检索三分类是怎么被 Prompt 出来、又是怎么在 E2E 里发现双实例 Bug 并引导修复的"。
- 优点：零风险、素材现成；缺点：不是"直播式"，说服力略弱。可与 A 组合使用。

### 方案 C：截图快剪
把三个 Prompt 链的关键截图按时间轴快剪 + 旁白。仅作 A/B 都来不及时的兜底。
