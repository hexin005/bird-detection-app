# 果园识鸟与远程驱离 App 技术方案

版本：MVP v0.1 · 日期：2026-10-29 · 状态：技术方向已确认，待实施

对应产品范围：[产品设计文档-MVP](./产品设计文档-MVP.md)。本文描述后续实现方案，当前 Demo 仍为纯前端模拟原型。

## 1. 实现目标

第一版实现“真实视频识鸟 + 模拟设备驱离”的移动应用，覆盖一个果园、一个监控点位和一个模拟声学驱鸟设备。优先交付 H5 与 Android，完成“检测—告警—人工确认—模拟执行—记录查询”的完整流程。

模型运行在电脑或服务器，手机负责展示和操作。真实硬件、自动驱离、手机离线推理及微信小程序适配留待后续版本。

## 2. 技术选型

| 层次 | 建议技术 | 职责与选择理由 |
| --- | --- | --- |
| 移动端 | uni-app + Vue 3 + TypeScript | 实现移动端页面，共用主要业务代码，分别验证 H5 和 Android |
| 前端状态 | Pinia | 管理登录信息、设备状态与当前任务；最终业务状态以后端为准 |
| 后端接口 | Python + FastAPI | 提供账号、监控任务、告警、控制指令和记录接口，方便与模型集成 |
| 模型推理 | 现有 YOLOv8 + PyTorch + OpenCV | 读取视频帧、识别鸟类、生成检测结果和告警抓拍 |
| 数据存储 | 优先沿用现有数据库；独立 MVP 可采用 SQLite | 保存账号、点位、告警和操作记录；图片与视频单独存文件，数据库记录路径及元信息 |
| 客户端通信 | HTTP + WebSocket | HTTP 负责查询与提交操作，WebSocket 更新检测信息、告警及执行状态 |
| 设备执行 | Python 模拟执行器 | 提供在线、离线、执行、停止和超时反馈，后续通过统一接口替换为真实设备连接 |

依赖版本以现有模型及项目的实际兼容性为准，验证通过后锁定。第一版不为追求最新版本更换模型或训练环境。

## 3. 整体架构

```text
演示视频 → 后端检测任务（YOLOv8 / OpenCV）→ 检测结果与告警规则
                                                 ↓
移动 App ← HTTP / WebSocket → FastAPI 业务服务 ←→ 数据库与媒体文件
                                   ↓
                            Python 模拟执行器
                                   ↓
                         执行回执 → 状态更新与记录
```

- **移动端**：监控、告警、控制、记录四个主要页面，以及登录与基础设置。
- **业务服务**：管理用户与点位、告警处理、指令状态和记录关联。
- **检测任务**：在后台持续读取视频并推理，不随用户切换页面而停止；耗时推理与接口请求处理隔离，避免阻塞接口。
- **模拟执行器**：接收执行与停止请求，返回模拟回执；状态由后端统一维护。

MVP 可部署在同一台电脑或服务器上，先按模块组织，不拆成多个微服务。手机通过可访问的服务地址连接；局域网演示时，手机与运行后端的电脑需要网络互通。

## 4. 现有成果复用

- **模型**：复用 `train-13bird-focus5-2/weights/best.pt` 及其 13 类鸟标签，优先验证现有推理环境。
- **网页项目**：逐项验证并复用模型调用、账号认证、记录等可用模块；持续检测、告警去重和设备回执缺失部分需要补齐，不能直接视为已完成。
- **当前 Demo**：沿用视觉风格、页面结构和操作流程，将原生 HTML/JS 整理为 Vue 组件，通过接口层逐步替换模拟数据。
- **现有网页端**：继续承担较复杂的管理功能，移动端聚焦巡护和现场处理。

## 5. 关键实现约定

### 视频与检测结果

视频传输与状态消息分开处理，WebSocket 主要传递检测信息、告警及指令状态。检测结果携带任务、点位、帧号或视频时间戳，确保画面与识别结果对应。

先完成一段预录视频在 H5 和 Android 上的播放与识别展示验证，再确定视频传输及叠框方案。第一版可以优先验证后端生成标注画面的方式，减少客户端叠框同步工作；具体协议、延迟和画面更新频率以实测决定。

视频结束、中断或检测停止时明确提示，不保留过时结果冒充当前监测。界面持续标明“录像演示”。

### 告警与控制

- 告警规则包含置信度阈值、连续检出条件和冷却时间；同一点位、同类鸟的连续检出合并为事件。
- 展示当前帧的检测数量，不把跨帧检测次数累计为独立鸟只数。
- 指令具有唯一标识，并由后端校验重复请求和设备状态，防止重复执行。
- 指令区分待执行、执行中、已完成、失败、已取消；无法确认结果时保留“结果未知”。
- 离线拒绝下发，超时不展示成功，重连不自动执行过期指令；停止结果以执行器回执为准。
- 告警、人工处理和驱离记录关联保存。模拟完成仅表示指令流程完成，不表示真实驱鸟有效。

### 数据恢复与连接

数据库作为历史记录与业务状态的持久化来源。WebSocket 断开后提示连接状态；重新连接或重新进入页面时，通过 HTTP 补拉最新状态与记录。第一版只提供 App 打开时的消息更新，不包含系统级后台推送。

## 6. 实施顺序

1. **验证核心链路**：确认指定模型和已有后端可运行，完成视频读取、识别、抓拍，以及手机端画面展示。
2. **实现移动端**：搭建 uni-app 工程，将 Demo 整理为 Vue 页面和组件，接入登录、监控与告警接口。
3. **打通业务流程**：实现模拟执行器、指令状态、停止操作及关联记录，完成一次完整巡护。
4. **验证与交付**：测试异常场景，分别验收 H5 与 Android，输出安装包、源码、运行说明和演示视频。

## 7. 测试与验收重点

| 验证项 | 通过标准 |
| --- | --- |
| 视频与推理 | 有鸟、无鸟、多鸟及遮挡样例能运行；画面和检测结果对应，结束与异常状态明确 |
| 持续监测 | 手机切换页面不停止检测；返回后可查询期间产生的告警 |
| 告警合并 | 连续检出不逐帧生成重复告警，数量口径准确 |
| 操作闭环 | 从告警发起驱离，回执与告警处理状态一致，并能追溯关联记录 |
| 异常处理 | 重复点击、离线、超时、停止和重连均符合状态约定，不产生意外重放或虚假成功 |
| 跨端兼容 | H5 与 Android 分别完成视频、登录、消息更新及核心流程验收 |

现有 Demo 的模拟状态测试可作为业务规则参考；真实后端接入后补充接口、持久化及端到端测试，不能用原型测试替代正式系统验收。
