# 果园识鸟与远程驱离 App 产品设计

版本：MVP v0.1 · 日期：2026-10-28 · 状态：已确认方向，待实现与验收

## 1. 产品定位

面向果园管理人员，提供鸟类监测、告警查看、远程驱离操作和事件追溯的移动应用。

第一版采用真实 YOLO 模型识别预录视频，通过模拟设备演示远程驱离流程，验证“发现鸟类—产生告警—人工确认—执行反馈—记录查询”的完整业务流程。界面明确标注录像来源和模拟设备，不将演示结果描述为真实硬件执行或实际驱鸟效果。

## 2. MVP 目标与边界

- 范围：一个演示果园、一个视频监控点位、一个模拟驱鸟设备。
- 平台：uni-app 移动端，优先验证 H5 与 Android。
- 模型：复用指定的 `train-13bird-focus5-2/weights/best.pt`，支持现有 13 类鸟。
- 推理位置：电脑或服务器运行模型，手机负责查看结果与发出操作。
- 驱离模式：人工确认后执行；第一版提供一种模拟声学驱离操作。
- 识别结果用于辅助判断；检测到鸟类不直接等同于发生鸟害。

## 3. 核心使用流程

1. 用户登录，进入演示果园监控页。
2. 后端读取演示视频并持续识别，App 展示视频画面与对应检测结果。
3. 达到告警条件后，生成包含设备、时间、鸟类和抓拍图片的事件。
4. 用户查看告警，选择“确认并驱离”或“忽略”。
5. 后端向模拟设备下达指令，App 展示执行状态及回执。
6. 检测事件、处理操作和驱离记录关联保存，支持后续查询。

用户离开监控页后，后端检测任务继续运行。第一版在 App 打开时提供告警更新，重新进入后补拉记录；系统级后台消息推送留待后续版本。

## 4. 主要页面与功能

| 页面 | 主要功能 |
| --- | --- |
| 监控 | 展示点位、演示视频、识别框、鸟类名称、置信度、当前画面检测数量和检测任务状态；标注“录像演示” |
| 告警 | 展示告警列表与详情，包括抓拍、发生时间、点位和识别结果；支持确认驱离、忽略及处理状态查看 |
| 控制 | 展示模拟设备在线状态；执行一次驱离、停止操作；查看执行中、完成、失败等状态；标注“模拟设备” |
| 记录 | 按时间和类型查看检测、告警处理与驱离记录；从告警追溯对应的操作及执行结果 |
| 登录与设置 | 账号登录与退出、服务连接状态、基础演示参数；复杂管理操作继续使用网页端 |

## 5. 关键业务规则

- **持续监测**：检测任务由后端管理，不依赖手机持续打开监控页；视频播放结束或中断时明确显示任务状态。
- **告警条件**：使用可配置的置信度阈值、连续检出条件和冷却时间；初始值通过演示视频测试确定。
- **重复合并**：同一点位、同类鸟在短时间内连续出现时合并告警，避免逐帧重复提醒。
- **数量口径**：展示当前画面检测数量，不将跨帧检测次数当作独立鸟只数。
- **指令状态**：区分待执行、执行中、已完成、失败、已取消；重复点击不产生重复执行。
- **异常处理**：离线时拒绝新指令；超时显示失败或结果未知，不显示执行成功；过期指令不在重连后自动执行。
- **停止操作**：取消尚未执行的任务，并向模拟执行器发送停止请求；状态以实际模拟回执为准。
- **效果表达**：指令完成仅代表模拟执行结束。后续视频画面变化作为观察记录，不据此宣称鸟类被成功驱离。

## 6. 技术与复用方案

整体结构：**演示视频 → Python/FastAPI 检测与告警服务 → 移动 App → 模拟设备执行器 → 事件记录**。

复用现有鸟类网页项目的模型调用、账号认证、检测记录、告警规则和模拟设备接口。移动端重新组织页面与操作流程，网页端继续承担管理功能。

优先补齐持续视频检测、点位与检测结果关联、告警去重、指令状态及回执。后续接入硬件时替换视频来源与设备执行器，尽量保持移动端业务流程稳定。

## 7. 第一版不包含

真实硬件控制、自动驱离、手机离线推理、微信小程序适配、多果园地图、复杂统计报表、模型在线训练与高级策略编排。申报书中的模型轻量化和云边协同研究属于后续工作，不作为本版已实现能力。

## 8. MVP 验收标准

- 能使用指定权重完成有鸟、无鸟、遮挡及多鸟视频的检测演示，记录成功与失败案例。
- 能完整演示一次“检测—告警—人工确认—模拟执行—记录查询”。
- 同一连续事件不会每帧重复告警；重复点击不会重复下发指令。
- 能演示设备离线、执行超时、停止操作和重新连接，状态与记录一致。
- 手机切换页面不停止后端监测；重新进入后可以查询期间产生的事件。
- 所有录像和模拟行为有清晰标识，历史记录不混入真实用户数据。
- H5 与 Android 的核心流程分别验收，不以一端通过替代另一端。

## 9. 实施顺序与参赛材料

1. 验证现有后端与模型可运行，完成一条视频检测及告警链路。
2. 实现移动端四个主要页面，打通模拟执行与记录查询。
3. 补齐异常场景测试与跨端验收，形成稳定演示版本。
4. 整理源码、复现指南、技术文档和演示视频；开发过程中持续保存 AI 对话及对应提交记录。

参赛材料如实区分已有研究／团队成果、本人贡献与本次新增工作。训练验证集指标、应用运行性能和实际驱鸟效果分别描述，不相互替代。
